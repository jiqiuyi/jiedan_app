# 第11批 · 反馈后台面板 · 设计思路

> 记录时间：2026-09-05
> 前置：1-10 批迭代完成，当前版本 v1.25.0+34
> 目标：补齐反馈闭环的管理侧能力，满足隐私合规，沉淀软著材料

## 一、本批目标（4 点补齐）

1. Web 后台：反馈处理状态标记 + 多条件筛选
2. 上报载荷：追加设备信息、App 版本号
3. App 端：新增「反馈信息上报开关」，满足隐私合规
4. 整体联调、异常兜底，完成闭环

## 二、已确认的设计决策（用户拍板）

1. **Web 管理后台沿用现有 `/admin` 路由**，在既有极简管理页 / 数据看板基础上扩展为「反馈管理」面板，**不新增独立域名页面**——域名解析（yurouyun.cn）与 HTTPS 尚未落地，避免依赖公网域名。
2. **设备信息上报最小化采集**（严格守住合规红线）：
   - 仅采集：设备型号、系统版本、App 版本号、build 号（共 4 项，非敏感）
   - **明确不采集**：IMEI、位置、通讯录、MAC、Android ID 等任何敏感标识
   - 采集实现用系统公开 API（device_info_plus / package_info_plus），不做任何越权读取
3. **「反馈信息上报开关」默认开启、可一键关闭**：
   - 开启：提交反馈时附带 4 项设备信息
   - 关闭：载荷中不含设备信息字段（服务端兼容缺失字段），不影响反馈提交本身
4. **异常兜底原则**：设备信息读取失败不阻断反馈提交；上报失败保留本地草稿并提示重试，不静默丢数据。

## 三、数据模型扩展

feedback 记录新增字段（后端 SQLite 存储，兼容旧数据）：
| 字段 | 类型 | 说明 |
|---|---|---|
| device_model | string | 设备型号（上报开关开启时） |
| os_version | string | 系统版本（Android/iOS） |
| app_version | string | App 版本号（如 1.26.0） |
| build_number | string | build 号（如 35） |
| status | string | 处理状态：pending / processing / resolved / ignored，默认 pending |
| processed_at | int | 状态变更时间戳（ms），未处理为 null |

## 四、接口设计

| 方法/路径 | 鉴权 | 说明 |
|---|---|---|
| POST /api/feedback | 用户 token | 载荷扩展 deviceModel/osVersion/appVersion/buildNumber（均可选，服务端长度+类型校验） |
| GET /api/feedback/all | 管理 token | 扩展 query 筛选：status、type、startTime、endTime、keyword |
| POST /api/admin/feedback/<id>/status | 管理 token | 标记处理状态 { status: pending/processing/resolved/ignored } |
| GET /admin（页面） | 管理 token | 反馈面板区块：列表 + 筛选 + 状态标记按钮 |

## 五、合规与安全要点

- 服务端对新增字段逐一二次校验（长度上限、类型），不信任客户端
- 上报开关关闭时，服务端不得因缺字段报错
- 不新增任何权限声明；AndroidManifest 不动
- 字段仅用于反馈排查，README 隐私政策同步补一句「反馈上报仅含设备型号/系统版本/App版本，可关闭」
